## 1. 心智模型

人看到的是文字，计算机首先处理编码后的字节；Tokenizer 再根据自己的规范化规则、切分算法和词表处理文本，并将每个 Token 映射成整数 ID。模型真正接收的是 Token ID，随后通过 Embedding 表取得向量。

```text
人类输入
  → Unicode 码点
  → UTF-8 字节
  → Tokenizer
  → Tokens
  → Vocabulary
  → Token IDs
  → Embedding 向量
```

{% hint style="warning" %}
Token 不是字符，Token ID 也不是 Unicode 编码。Token 和 ID 都由具体模型的 Tokenizer 决定。
{% endhint %}

## 2. 五个容易混淆的概念

| 概念 | 定义 | 示例 |
| --- | --- | --- |
| 字符 | 人理解的文字单位，但不总能与程序中的一个位置严格对应 | `学`、`A`、`🙂` |
| Unicode 码点 | Unicode 为抽象字符分配的编号 | `学 → U+5B66` |
| UTF-8 字节 | 码点在文件或网络中的具体字节表示，长度可变 | `学 → 3 bytes` |
| Token | Tokenizer 根据规则与词表切出的模型单位，可能是词、子词、字符或字节片段 | `learning → learn + ing` |
| Token ID | Token 在模型词表中的整数索引 | `learn → 4556` |

表中的 Token ID 只用于说明。不同模型的词表不同，同一个 Token 的 ID 也可能不同。

## 3. 实验 A：字符与字节

先不要运行代码。请预测下面文本的 Python 长度和 UTF-8 字节数：

```text
AI学习🙂
```

- 我预测 `len(text) = ____`
- 我预测 `len(text.encode("utf-8")) = ____`

然后运行：

```python
text = "AI学习🙂"

print("原始文本：", text)
print("Python len：", len(text))
print("Unicode 码点：", [f"U+{ord(ch):04X}" for ch in text])

utf8 = text.encode("utf-8")
print("UTF-8 字节：", list(utf8))
print("字节数量：", len(utf8))
```

### 结果解释

`len(text)` 是 5，因为这里的 Python 字符串包含 5 个 Unicode 码点。

UTF-8 字节数是 12：

- `A` 和 `I` 各占 1 字节；
- `学` 和 `习` 各占 3 字节；
- `🙂` 占 4 字节。

注意：Python 的 `len` 也不总等于人眼看到的“字符数”。由多个码点组合而成的 emoji 或带组合音标的文字会形成反例。

## 4. 实验 B：Token 与 Token ID

安装依赖：

```bash
pip install transformers
```

运行下面的代码：

```python
from transformers import AutoTokenizer

text = "AI学习🙂"
tokenizer = AutoTokenizer.from_pretrained("bert-base-chinese")

tokens = tokenizer.tokenize(text)
token_ids = tokenizer.convert_tokens_to_ids(tokens)

print("文本：", text)
print("Tokens：", tokens)
print("Token IDs：", token_ids)
print("解码结果：", tokenizer.decode(token_ids))
```

换成其他模型后，Tokens 和 Token IDs 很可能改变。这是因为不同 Tokenizer 可能使用不同的规范化规则、切分算法与词表。

## 5. 自我检查

问题：同一段文本分别交给两个不同的 LLM，它们得到的 Token ID 序列是否一定相同？

**答案：不一定相同。**

模型可能采用不同的规范化规则、分词算法和词表，所以 Tokens 与 Token IDs 都可能不同。UTF-8 字节属于文本编码层，Token ID 属于模型词表层。
