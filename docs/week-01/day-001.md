# Day 001 笔记：Unicode、字符、字节和 Token

{% hint style="success" %}
**核心结论：** 模型不直接读取文字。文本先被解码为 Unicode 字符串，再由 Tokenizer 切分并映射为 Token ID，最后通过 Embedding 表变成向量。
{% endhint %}

## 1. 完整数据流

```text
文件或网络中的字节
        ↓ 按字符编码解码（通常是 UTF-8）
Unicode 字符串（码点序列）
        ↓ Tokenizer：规范化、切分、查词表、加特殊 Token
Token 序列
        ↓ 词表映射
Token ID 序列
        ↓ Embedding lookup
向量序列
        ↓ Transformer
上下文化表示 / 输出概率
```

关键边界：

- UTF-8 负责“字节怎样表示文字”。
- Tokenizer 负责“文字怎样切成模型词表中的单位”。
- Token ID 只是词表索引，本身没有连续的数值大小含义。
- Embedding 才把离散编号转换为可训练的连续向量。

## 2. 概念对照

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| 字形（glyph） | 屏幕上看到的图形 | 同一个“a”在不同字体中的外观 |
| 字素簇（grapheme cluster） | 用户感知的一个字符 | `é`、家庭 emoji |
| Unicode 码点 | Unicode 分配的抽象编号 | `学` 是 `U+5B66` |
| UTF-8 字节 | 码点的存储或传输形式 | `学` → `E5 AD A6` |
| Token | Tokenizer 切出的模型单位 | 字、词、子词或特殊符号 |
| Token ID | Token 在词表中的整数索引 | `[CLS]` → `101` |

“一个字”不一定对应一个码点，也不一定对应一个 Token：

- `é` 可以是一个码点 `U+00E9`；
- 也可以是 `e` 与组合重音 `U+0301` 两个码点；
- 家庭 emoji 看起来是一个图形，但由多个码点和连接符组成；
- Tokenizer 又可能把这些内容切成一个、多个 Token，或映射成未知 Token。

## 3. Unicode 与 UTF-8

Unicode 定义字符与码点；UTF-8 定义码点如何编码成字节。两者不是同一层。

UTF-8 使用 1～4 个字节表示一个 Unicode 码点：

| 码点范围 | 字节数 | 模板 |
| --- | ---: | --- |
| `U+0000`～`U+007F` | 1 | `0xxxxxxx` |
| `U+0080`～`U+07FF` | 2 | `110xxxxx 10xxxxxx` |
| `U+0800`～`U+FFFF` | 3 | `1110xxxx 10xxxxxx 10xxxxxx` |
| `U+10000`～`U+10FFFF` | 4 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

例：`学` 的码点是 `U+5B66`，其 UTF-8 编码为三个字节 `E5 AD A6`。

```text
U+5B66 = 0101 1011 0110 0110

按 3 字节模板填入：
1110xxxx 10xxxxxx 10xxxxxx
11100101 10101101 10100110
   E5       AD       A6
```

因此，字符数量、码点数量和字节数量不能混用。

## 4. Python 实验记录

### 4.1 长度、码点和 UTF-8 字节

```python
text = "AI学习🙂"

print("文本：", text)
print("Python len：", len(text))
print("UTF-8 字节：", text.encode("utf-8"))
print("UTF-8 字节数：", len(text.encode("utf-8")))

for ch in text:
    print(ch, f"U+{ord(ch):04X}", ch.encode("utf-8").hex(" "))
```

实验输出：

```text
文本： AI学习🙂
Python len： 5
UTF-8 字节： b'AI\xe5\xad\xa6\xe4\xb9\xa0\xf0\x9f\x99\x82'
UTF-8 字节数： 12
A U+0041 41
I U+0049 49
学 U+5B66 e5 ad a6
习 U+4E60 e4 b9 a0
🙂 U+1F642 f0 9f 99 82
```

结论：Python 3 的 `str` 按 Unicode 码点处理；`bytes` 才是编码后的原始字节。这个例子中 5 个码点对应 12 个 UTF-8 字节。

### 4.2 “看起来相同”不等于“底层相同”

```python
import unicodedata

a = "é"          # U+00E9
b = "e\u0301"   # U+0065 + U+0301

print(len(a), len(a.encode("utf-8")), [f"U+{ord(c):04X}" for c in a])
print(len(b), len(b.encode("utf-8")), [f"U+{ord(c):04X}" for c in b])
print("原始比较：", a == b)
print("NFC 后比较：", unicodedata.normalize("NFC", a) == unicodedata.normalize("NFC", b))
```

实验输出：

```text
1 2 ['U+00E9']
2 3 ['U+0065', 'U+0301']
原始比较： False
NFC 后比较： True
```

结论：字符串比较比较的是码点序列，而不是屏幕上的外观。规范化可以把规范等价的写法变成一致形式。

### 4.3 一个 emoji 也可能包含多个码点

```python
family = "👨‍👩‍👧‍👦"

print("Python len：", len(family))
print("UTF-8 字节数：", len(family.encode("utf-8")))
print([f"U+{ord(ch):04X}" for ch in family])
```

实验输出：

```text
Python len： 7
UTF-8 字节数： 25
['U+1F468', 'U+200D', 'U+1F469', 'U+200D', 'U+1F467', 'U+200D', 'U+1F466']
```

其中 `U+200D` 是零宽连接符。界面显示的一个图形由 7 个码点组成，所以不能用 `len(text)` 判断用户感知字符数。

## 5. Tokenizer 实验记录

使用 `bert-base-chinese`：

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-chinese")
text = "AI学习🙂"

encoded = tokenizer(
    text,
    return_offsets_mapping=True,
    return_special_tokens_mask=True,
)

tokens = tokenizer.convert_ids_to_tokens(encoded["input_ids"])

for key, value in encoded.items():
    print(key, value)
print("tokens", tokens)
```

实验输出：

```text
input_ids [101, 100, 2110, 739, 100, 102]
token_type_ids [0, 0, 0, 0, 0, 0]
attention_mask [1, 1, 1, 1, 1, 1]
special_tokens_mask [1, 0, 0, 0, 0, 1]
offset_mapping [(0, 0), (0, 2), (2, 3), (3, 4), (4, 5), (0, 0)]
tokens ['[CLS]', '[UNK]', '学', '习', '[UNK]', '[SEP]']
```

字段解释：

| 字段 | 作用 |
| --- | --- |
| `input_ids` | Token 在词表中的索引，真正送入模型的整数 |
| `attention_mask` | `1` 表示有效位置，`0` 通常表示 padding |
| `token_type_ids` | BERT 用于区分句子 A 与句子 B |
| `special_tokens_mask` | 标出 `[CLS]`、`[SEP]` 等特殊 Token |
| `offset_mapping` | Token 对应原始字符串的起止位置，区间为左闭右开 |

本次结果中的重要观察：

- `[CLS]` 和 `[SEP]` 是模型需要的特殊 Token，不直接对应原文，因此 offset 是 `(0, 0)`。
- `AI` 整体变成 `[UNK]`，说明该 Tokenizer 的处理规则与词表无法覆盖这里的输入形式。
- `学`、`习` 分别存在于词表中。
- emoji 也变成 `[UNK]`。
- 两个 `[UNK]` 虽然 ID 相同，但进入 Transformer 后会因上下文和位置不同而得到不同的上下文化表示。

## 6. Token ID 到 Embedding

设词表大小为 `V`，隐藏维度为 `d`，模型维护一个可训练矩阵：

\[
E \in \mathbb{R}^{V \times d}
\]

Token ID `i` 的初始词向量就是矩阵第 `i` 行：

\[
x_i = E[i]
\]

实际输入通常还会加上位置等信息。以 BERT 为例：

\[
h_i^{(0)} = E_{token}[i] + E_{position}[i] + E_{segment}[i]
\]

随后 Transformer 根据上下文更新表示。Embedding lookup 只是查表，不是“ID 越接近，语义越相近”。

## 7. 易错点

1. **Unicode 不是 UTF-8。** Unicode 是字符编号体系，UTF-8 是编码方案。
2. **一个字符不固定占 1 个字节。** UTF-8 中英文、汉字和 emoji 的字节数不同。
3. **`len(text)` 不是用户感知字符数。** 它也不是 UTF-8 字节数。
4. **Token 不等于单词。** Token 可以是字、子词、符号、字节片段或特殊标记。
5. **Token ID 不是语义坐标。** ID 只是词表索引。
6. **Tokenizer 不是通用配件。** 模型必须配套使用训练时的 Tokenizer 和词表。
7. **解码错误不能靠 Tokenizer 修复。** 字节必须先按正确编码解码成 Unicode 字符串。

## 8. 一页回顾

```text
码点：字符在 Unicode 中的编号
UTF-8：把码点编码成 1～4 个字节
字素簇：用户感知的一个字符，可能包含多个码点
Token：Tokenizer 依据算法和词表切出的单位
Token ID：Token 在词表中的整数索引
Embedding：用 Token ID 查出的可训练向量
```
