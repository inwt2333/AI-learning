# Day 004：字符、单词、子词与字节级分词

{% hint style="info" %}
**同一段文本为什么可以被切成完全不同的 Token？字符、单词、子词和字节这四种粒度，分别把什么当作模型的基本输入单位？**
{% endhint %}

## 学习目标

完成本节后，你应该能够：

1. 严格区分字符、单词、子词、字节和 Token；
2. 解释四种粒度各自的文本 → Token → ID 数据流；
3. 说明“字符级”中的字符为什么需要进一步定义；
4. 区分纯字节模型、byte-level BPE 与 byte fallback；
5. 解释子词为何在词表大小、序列长度和 OOV 之间取得折中；
6. 根据语言、任务、数据和计算预算选择粒度；
7. 手写一个最小的最长匹配子词切分器，并分析其边界；
8. 从 Embedding 参数量与注意力复杂度解释粒度的工程代价。

## 1. 分词粒度其实是在决定模型的“原子”

神经网络不能直接接收人类看到的文字。Tokenizer 必须先把字符串映射为有限 ID 序列：

```text
原始字符串
  ↓ 规范化
规范化字符串
  ↓ 选择切分边界和基本单位
Token 字符串/符号序列
  ↓ 词表查找
Token ID 序列
  ↓ Embedding 查表
向量序列 X ∈ R^(n×d)
```

其中：

* `n` 是切分后的序列长度；
* `d` 是模型隐藏维度；
* 每一种粒度都会同时影响词表大小 `|V|` 和序列长度 `n`；
* 模型从哪一层开始组合语义，也由基本单位决定。

例如，同一句“ChatGPT正在学习!”可以有多种表示：

```text
单词式：ChatGPT / 正在 / 学习 / !
子词式：Chat / GPT / 正在 / 学习 / !
字符式：C / h / a / t / G / P / T / 正 / 在 / 学 / 习 / !
字节式：67 / 104 / 97 / ... / 228 / 185 / 160 / 33
```

这些切分没有一个脱离任务和模型的“唯一正确答案”。它们是在不同成本之间做选择。

{% hint style="warning" %}
粒度描述的是 Tokenizer 允许模型直接查表的单位，不代表模型只能理解这一层。字符模型可以在高层组合出词，子词模型也可以在高层组合出短语。
{% endhint %}

## 2. 先把四个概念定义严格

### 2.1 字符级：这里的“字符”究竟是什么

“字符”在日常语言中很直观，在程序中却可能指：

1. Unicode 码点；
2. 用户感知字符，也就是扩展字素簇；
3. 某种文字系统中的书写单位；
4. Python 字符串迭代得到的元素。

大多数简单的 character-level 实现把一个 Unicode 码点当作一个单位。Python 的：

```python
list(text)
```

也大体沿码点切分，而不是严格沿用户感知字符切分。

例如组合序列：

```python
text = "e\u0301"
print(list(text))
print(len(text))
```

可能得到两个码点：

```text
['e', '́']
2
```

但用户通常把它看作一个“é”。emoji 家庭、肤色修饰符和 ZWJ 序列也可能由多个码点组成。

所以说“字符级模型”时必须继续追问：

> 它使用 Unicode 码点、字素簇，还是经过哈希/编码后的字符 ID？

### 2.2 单词级：语言中的词不等于按空格切分

词级方法希望一个 Token 对应一个 word：

```text
I love NLP. → I / love / NLP / .
```

但“词”的边界依赖语言和任务：

* 英文空格能提供线索，但 `don't`、`New York`、`state-of-the-art` 和标点仍有歧义；
* 中文通常不写词间空格，`研究生命起源` 可以涉及不同切分解释；
* 德语等语言可以构造很长的复合词；
* 土耳其语等语言通过丰富词缀生成大量词形；
* URL、代码、emoji 和中英混排不遵守普通自然语言边界。

Unicode UAX #29 提供默认词边界规则，但也明确指出，中文、日文、泰文等语言的可靠词边界通常需要词典或其他语言相关机制。

因此，词级分词通常先需要一个 **pre-tokenizer（预切分器）** 或专门分词模型：

```text
原始文本
  ↓ 规则、词典或统计模型
词序列
  ↓ 词级词表
词 ID 序列
```

### 2.3 子词级：从数据中学习的可复用字符串片段

子词介于单词与字符之间。常见单位可能是：

```text
unhappiness → un / happi / ness
tokenization → token / ization
量子纠错码 → 量子 / 纠错 / 码
```

但子词不是语言学上的“词素”同义词。BPE、WordPiece 和 Unigram 主要根据训练语料与各自目标学习单位：

* 有时恰好对应前缀、词根或词；
* 有时只是统计上经常共同出现的字符片段；
* 有时会跨越人类认为自然的语素边界；
* 不同训练语料会得到不同子词词表。

一个常见子词系统包含两层：

```text
预切分：把文本分成较粗片段
  ↓
子词模型：在每个片段内部应用 BPE/WordPiece/Unigram 等规则
```

SentencePiece 的重要特点之一是可以直接从原始句子训练，把空格也编码进表示，从而不要求先提供按词切好的语料。

### 2.4 字节级：先把字符串编码成 UTF-8

纯字节级方法先执行：

```python
raw_bytes = text.encode("utf-8")
```

每个字节都是 0–255 之间的整数，所以基础符号集合只需覆盖 256 种值。

ASCII 范围内的英文字符通常占 1 个 UTF-8 字节；常用中文汉字通常占 3 个；emoji 往往占 4 个或更多字节组合。因此：

```text
A    → [65]
学   → [229, 173, 166]
🙂   → [240, 159, 153, 130]
```

只要保留完整 256 字节集合，任意合法 UTF-8 文本都可以无损表示。

## 3. “字节级 Tokenizer”其实可能指三件事

这一术语非常容易混用。

### 3.1 纯字节模型

纯字节模型直接把每个字节作为一个模型 Token：

```text
文本 → UTF-8 → 单字节序列 → Embedding
```

ByT5 就属于面向字节序列的模型。优势是覆盖稳定、无需大型子词词表；代价是序列更长。

### 3.2 Byte-level BPE

Byte-level BPE 先把字节作为基础符号，再学习把常见相邻字节序列合并成更长 Token：

```text
文本 → UTF-8 字节 → 可显示的字节符号
     → BPE 合并 → Token ID
```

它的最终 Token **不一定是单个字节**。常见字符串可能被一个 Token 覆盖，罕见字符串仍能退回较细字节单位。

GPT-2 系列 Tokenizer 常被称为 byte-level BPE。其 Token 字符串有时看起来像奇怪的 Unicode 符号，这是因为实现会先把 256 个字节映射到一组可处理的 Unicode 字符，再执行 BPE；这些显示符号不等于原文字符。

### 3.3 子词模型中的 byte fallback

某些 SentencePiece/Unigram/BPE Tokenizer 主要使用普通子词；当某个字符无法由词表覆盖时，再退回表示该字符 UTF-8 编码的字节 Token：

```text
常见文本 → 普通子词
罕见字符 → <0xF0> / <0x9F> / ...
```

这叫 byte fallback。它不是“全部文本始终逐字节处理”，而是一条兜底路径。

| 名称 | 常规输入单位 | 是否学习合并 | 典型序列长度 |
| --- | --- | --- | --- |
| 纯字节模型 | 单个 UTF-8 字节 | 否 | 通常最长 |
| Byte-level BPE | 字节起步后的合并片段 | 是 | 比纯字节短 |
| 带 byte fallback 的子词 | 普通子词，必要时退回字节 | 取决于主算法 | 常见文本较短，罕见字符变长 |

## 4. 四种粒度的完整数据流

### 4.1 词级

```text
"我喜欢自然语言处理"
  ↓ 中文分词器
["我", "喜欢", "自然语言处理"]
  ↓ 词级词表查询
[17, 302, 4819]
```

若“自然语言处理”不在词表，传统词级方法可能得到 `<UNK>`。

### 4.2 字符级

```text
"我喜欢自然语言处理"
  ↓ 按码点切分
["我", "喜", "欢", "自", "然", "语", "言", "处", "理"]
  ↓ 字符词表或哈希映射
字符 ID 序列
```

完整词从未见过也不要紧，只要各字符能表示。但模型必须在高层重新组合“自然语言处理”。

### 4.3 子词级

```text
"我喜欢自然语言处理"
  ↓ 规范化与预切分
  ↓ 学得的子词模型
["我", "喜欢", "自然", "语言", "处理"]
  ↓ 子词词表
Token ID 序列
```

上面的具体切分只是示意。真实输出完全取决于 checkpoint 对应的 Tokenizer。

### 4.4 纯字节级

```text
"学"
  ↓ UTF-8 encode
[229, 173, 166]
  ↓ 256 项基础映射
3 个字节 ID
```

字节模型不需要先知道“学”这个码点，但需要从多个字节组合中学习它。

## 5. 实验：同一段文本在四种粒度下有多长

下面的代码故意不依赖第三方分词库，以便逐行理解。它不是生产级 Tokenizer，而是用于观察粒度差异。

```python
import re

text = "ChatGPT正在学习!"


def word_like_tokenize(s: str) -> list[str]:
    """只做演示：连续英文、连续中文、标点分别成组。"""
    return re.findall(
        r"[A-Za-z]+|[\u4e00-\u9fff]+|[^\w\s]",
        s,
    )


def longest_match(
    s: str,
    vocab: set[str],
) -> list[str]:
    """从左到右选择词表中最长的可匹配片段。"""
    result = []
    i = 0
    max_len = max(map(len, vocab))

    while i < len(s):
        for width in range(
            min(max_len, len(s) - i),
            0,
            -1,
        ):
            piece = s[i : i + width]
            if piece in vocab:
                result.append(piece)
                i += width
                break
        else:
            result.append("<UNK>")
            i += 1

    return result


char_tokens = list(text)
word_tokens = word_like_tokenize(text)

subword_vocab = {
    "Chat",
    "GPT",
    "正在",
    "学习",
    "!",
}
subword_tokens = longest_match(
    text,
    subword_vocab,
)

byte_tokens = list(text.encode("utf-8"))

print("text:", text)
print(
    "character:",
    char_tokens,
    "count =",
    len(char_tokens),
)
print(
    "word-like:",
    word_tokens,
    "count =",
    len(word_tokens),
)
print(
    "subword:",
    subword_tokens,
    "count =",
    len(subword_tokens),
)
print(
    "UTF-8 bytes:",
    byte_tokens,
    "count =",
    len(byte_tokens),
)
print(
    "byte round-trip:",
    bytes(byte_tokens).decode("utf-8"),
)
```

本次实测输出：

```text
text: ChatGPT正在学习!
character: ['C', 'h', 'a', 't', 'G', 'P', 'T', '正', '在', '学', '习', '!'] count = 12
word-like: ['ChatGPT', '正在学习', '!'] count = 3
subword: ['Chat', 'GPT', '正在', '学习', '!'] count = 5
UTF-8 bytes: [67, 104, 97, 116, 71, 80, 84, 230, 173, 163, 229, 156, 168, 229, 173, 166, 228, 185, 160, 33] count = 20
byte round-trip: ChatGPT正在学习!
```

### 5.1 为什么不能据此断言“词级最好”

这个例子中，词式规则只产生 3 个单位，看起来最短，但它把连续中文 `正在学习` 整体当成一个“词”。这并不是真实中文词边界，也意味着词表必须直接收录这个长字符串，否则可能变成 `<UNK>`。

子词示例产生 5 个单位，因为我们事先给了一个刚好覆盖文本的玩具词表。如果移除 `正在`：

```python
subword_vocab.remove("正在")
print(longest_match(text, subword_vocab))
```

最长匹配器会在“正”和“在”处输出 `<UNK>`。真实子词 Tokenizer 通常会保留字符或字节级基础符号来提高覆盖率。

因此，比较 Token 数时必须同时报告：

* 使用的具体 Tokenizer/checkpoint；
* 词表大小；
* 是否产生 unknown；
* 训练语料与测试语料；
* 规范化和预切分规则。

### 5.2 最长匹配不等于 BPE 训练

`longest_match()` 只负责在一个已经给定的词表中编码。它没有解释这个词表如何学出来。

BPE 的训练阶段会从小单位开始，反复选择高频相邻符号对并合并，形成新的词表项；编码阶段再按学到的合并规则切分。Day 5 将手工追踪完整 BPE 合并过程。

## 6. 模型怎样从更小单位恢复词义

假设“自然语言处理”被表示为：

```text
自然 / 语言 / 处理
```

Embedding 层最初只查到三个静态向量：

$$
x_1=E[\text{自然}],\quad
x_2=E[\text{语言}],\quad
x_3=E[\text{处理}]
$$

加上位置等信息后，它们进入 Transformer。自注意力与前馈网络让每个位置逐层结合上下文：

$$
H^{(\ell+1)}
=\operatorname{Block}_{\ell}
\left(H^{(\ell)}\right)
$$

高层隐藏状态可以表示整个术语在当前句子中的意义。模型不要求每个概念一开始就对应一个词表行。

四种粒度的区别在于组合从哪里开始：

| 粒度 | Embedding 层直接提供 | 模型还需要组合 |
| --- | --- | --- |
| 词级 | 整词的初始向量 | 词 → 短语/句子 |
| 子词级 | 常见片段的初始向量 | 子词 → 词 → 更高结构 |
| 字符级 | 字符的初始向量 | 字符 → 词 → 更高结构 |
| 字节级 | 字节的初始向量 | 字节 → 字符 → 词 → 更高结构 |

“更细粒度”并不必然让模型无法理解，只是把更多组合工作交给网络，同时拉长序列。

## 7. 词表大小与序列长度的两端拉扯

设词表大小为 `|V|`，隐藏维度为 `d`，输入 Embedding 参数量为：

$$
P_{\text{emb}}=|V|d
$$

如果输出层不与输入 Embedding 共享，生成模型还可能需要近似同规模的输出权重：

$$
P_{\text{out}}\approx |V|d
$$

词表越大，常见长字符串越可能直接成为一个 Token，序列可能变短；但 Embedding 和输出层更大，低频词表行也更难训练充分。

词表越小，参数行更少、覆盖更容易；但序列通常变长。标准全注意力需要构造近似 `n×n` 的注意力关系：

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}
\left(
\frac{QK^\top}{\sqrt{d_k}}
\right)V
$$

其注意力分数计算和矩阵存储随 `n` 近似二次增长：

$$
O(n^2)
$$

### 7.1 一个数量级例子

假设某文本：

* 子词表示长度为 128；
* 字节表示长度为 384；
* 其他条件相同。

只看注意力分数元素数：

$$
128^2=16{,}384
$$

$$
384^2=147{,}456
$$

后者是前者的：

$$
\left(\frac{384}{128}\right)^2=9
$$

倍。

这不代表整个模型必然慢 9 倍，因为实际系统还有线性层、内存带宽、批处理、下采样和优化内核等因素；但它解释了为什么纯字符/字节模型需要认真处理长序列成本。CANINE 使用下采样减少进入深层 Transformer 的长度，就是一种架构层面的应对。

## 8. 四种粒度的优势、代价与失败方式

| 粒度 | 主要优势 | 主要代价 | 典型失败方式 |
| --- | --- | --- | --- |
| 词级 | 序列短，单位较易解释 | 词表巨大，依赖分词，OOV 严重 | 新词折叠为 `<UNK>`，形态变化稀疏 |
| 子词级 | 覆盖、长度和词表规模较平衡 | 切分依赖语料，未必符合词素 | 低资源语言被过度切碎，边界标记易误读 |
| 字符级 | 拼写细节强，词表较小 | 序列长，需要学习组合词义 | 码点不等于字素簇，Unicode 词表仍有 OOV |
| 纯字节级 | 固定 256 基础单位，覆盖任意 UTF-8 | 序列通常最长，可读性差 | 多字节字符被拆开，计算成本上升 |

### 8.1 词级的稀疏性

假设词表分别收录：

```text
run / runs / running / ran
```

四个词形拥有四行独立 Embedding。模型需要从数据中学习它们的关系。对形态丰富语言，词形组合会快速扩张。

### 8.2 子词级的共享

子词可以让多个词复用片段：

```text
play / ##ing
read / ##ing
walk / ##ing
```

`##` 在一些 WordPiece 词表中表示“该片段不是词首”。它是边界约定，不是普通的两个井号字符。

SentencePiece 常用 `▁` 表示被编码进模型的空格/词首信息；GPT-2 风格实现中常见的 `Ġ` 也与前导空格有关。不同 Tokenizer 的标记不能互换解释。

### 8.3 字符/字节级的鲁棒性不是免费午餐

更细单位通常更能保留拼写错误、罕见名字和噪声。例如一个词拼错一个字母时，词级模型可能直接 OOV，而字符模型只改变一个位置。

但更长序列意味着：

* 可放入固定上下文窗口的原文更少；
* 训练和推理计算增加；
* 模型需要更多层次完成局部组合；
* 对人类进行错误分析更困难。

ByT5 的研究发现字节级模型在噪声以及拼写、发音敏感任务上有优势，同时也专门分析了训练计算和推理速度权衡。这说明“更鲁棒”和“更高效”不是同一个结论。

## 9. 怎样为任务选择粒度

没有一种粒度对所有任务都最优。可以按下面顺序思考。

### 9.1 先问是否必须兼容预训练模型

如果使用现成 BERT、T5 或 LLM，通常必须使用随 checkpoint 发布的 Tokenizer。不能因为自己的任务更适合字符级，就直接把字符 ID 送入原模型；Embedding 行与 ID 语义完全不匹配。

此时更现实的选择是：

* 保持原 Tokenizer；
* 调整预处理和最大长度；
* 必要时少量扩词表并继续训练；
* 或选择一个原本就采用更合适 Tokenizer 的 checkpoint。

### 9.2 再看任务依赖什么信息

| 任务/场景 | 重要信息 | 常见考虑 |
| --- | --- | --- |
| 通用 LLM | 语义、覆盖、生成效率 | 子词或 byte-level BPE 常见 |
| 拼写纠错、发音、噪声鲁棒 | 精细字符/字节变化 | 字符或字节可能有优势 |
| 中文分词、词性标注 | 词边界本身 | 字符/子词输入 + 序列标注较自然 |
| NER、抽取式问答 | 原文位置对齐 | 需要 offset mapping，粒度越细对齐越直接但序列更长 |
| 搜索与关键词系统 | 词和短语匹配 | 可能同时保留词级索引与字符 n-gram |
| 低资源或多语言 | 词表公平覆盖 | 检查不同语言的 fertility 和 byte fallback |
| 代码模型 | 空白、符号、标识符 | 必须保留格式，避免普通自然语言规则破坏代码 |

### 9.3 用数据而不是直觉评估

至少测量：

1. **fertility**：每个原始词平均被切成多少 Token；
2. 每字符或每字节 Token 数；
3. unknown/byte fallback 比例；
4. 截断率和可容纳的原文长度；
5. 不同语言、领域和群体之间的差异；
6. 下游任务指标；
7. 训练/推理吞吐量、显存与延迟。

如果一个多语言 Tokenizer 对英文平均每词 1.2 个 Token，对目标语言平均每词 5.8 个 Token，那么同样的上下文窗口和计费方式会对目标语言更不利。只看总体平均值可能掩盖这个问题。

## 10. 容易混淆的边界

### 10.1 Token 不等于显示出来的字符串

某些 Tokenizer 内部 Token 可能对应：

* 带前导空格的片段；
* 字节映射后的代理符号；
* 规范化后的字符串；
* 特殊控制含义。

因此，`convert_ids_to_tokens()` 的显示结果不一定能直接拼接成人类原文。应使用同一个 Tokenizer 的 `decode()` 恢复文本。

### 10.2 字符级不等于没有词表

普通字符级模型仍可能维护一个有限 Unicode 字符表，罕见字符仍可能 OOV。只有完整字节覆盖、哈希等机制才能避免维护巨大字符枚举；它们也各自带来碰撞或长序列等代价。

### 10.3 子词级不等于永远无 `[UNK]`

是否能完全覆盖输入，取决于基础字母表、字符覆盖、规范化和 byte fallback。BERT WordPiece 与带完整字节回退的 Tokenizer 行为不同。

### 10.4 一个汉字不必等于一个 Token

它可能：

* 在字符式中文 BERT 中成为一个 Token；
* 与相邻字合并成一个子词 Token；
* 在纯字节模型中成为三个字节 Token；
* 因不在字符覆盖范围而变成 `[UNK]`；
* 在 byte fallback 中退回三个字节单位。

必须以具体 Tokenizer 实测。

## 11. 常见误区

### 误区 1：英文按空格切分就是词级 Tokenizer

不完整。标点、缩写、所有格、连字符、多词表达和特殊字符串仍需要规则；其他语言也未必有空格边界。

### 误区 2：子词一定具有语言学意义

错误。子词算法优化的是统计或概率目标，得到的片段可能与词素重合，也可能只是高频字符组合。

### 误区 3：字节级就是每个最终 Token 只有一个字节

错误。纯字节模型如此；byte-level BPE 会继续合并多个字节，带 byte fallback 的子词模型只在必要时退回字节。

### 误区 4：粒度越细，模型越强

错误。细粒度提高覆盖和拼写鲁棒性，却增加序列长度与组合难度。质量取决于模型架构、数据和预算。

### 误区 5：粒度越粗，计算一定越少

不完整。粗粒度可能缩短序列，却会增大 Embedding/输出层，并带来稀疏长尾和 OOV。

### 误区 6：可以为同一模型随意更换 Tokenizer

错误。Token ID 与 Embedding 行是固定契约。大规模更换切分和 ID 后，旧权重不能直接正确解释输入。

### 误区 7：Token 数能直接跨模型比较语言能力

错误。Token 数能反映表示效率和成本，但模型质量还受到训练数据、架构、参数量与目标影响。

整词 → ID

保留拼写细节，但“字符”需明确定义，序列更长

纯字节 ≠ byte-level BPE ≠ byte fallback

两类主要成本：

先保证 checkpoint 与 Tokenizer 兼容
