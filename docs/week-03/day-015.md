## 1. 词汇鸿沟：缺的是"语义几何"

回看 Day 011 的 TF-IDF：每个词占据词表中独立的一维。"自然语言"和"NLP"是两个互不相关的维度，余弦恒为 0——无论文档怎么写，这两个词在几何上永远正交。Day 014 的 BM25 实验也实测了这一点：查询"NLP"返回空。

词袋方法缺的不是权重（TF-IDF、BM25 都在调权重），而是**几何**：意思相近的词之间没有"近"这个概念。要补上它，必须先回答一个语言学问题——

> 词的"意思"能不能从可观测的数据里统计出来？

## 2. 分布式假设：语义藏在分布里

**分布式假设**（distributional hypothesis）：出现在相似上下文中的词，意思也相似。它有两个经典出处：

* Harris（1954）：如果两个词在多种语境中分布相近，它们大概率语义相近；
* Firth（1957）的名言："You shall know a word by the company it keepers"——观其伴而知其义。

注意术语的三个层次，面试和文献里经常被搅在一起：

* **分布式假设**：一个语言学论断——语义与上下文分布相关。它是假设，不是定理；
* **分布式表示**（distributed representation）：一种工程选择——用一串低维稠密的数值（很多维度共同参与）表示一个词，与 one-hot 的"一个维度管一个词"（localist representation，局部式表示）相对；
* **上下文分布**（distribution）：一个可统计对象——某个词周围出现过哪些词、各出现多少次。

分布式假设说"分布决定语义"；分布式表示是"把分布（或从中提炼的信息）压缩成稠密向量"的实现手段。词向量有效，是对分布式假设的实证支持，而不是证明。

## 3. 词—上下文矩阵：把假设变成数据结构

操作化分三步：

1. 定义**上下文**：本文用滑动窗口，$$\operatorname{window}=1$$ 表示只看左右各 1 个词（真实系统常用 5–10）；
2. 数**共现**：目标词 $$w$$ 的窗口里每出现一个词 $$c$$，矩阵单元 $$M[w,c]$$ 加 1；
3. 读**向量**：词 $$w$$ 的表示就是矩阵的第 $$w$$ 行——"它在什么上下文里出现、各多少次"。

```
语料（已分词的句子）
  → 对每个位置，取左右 window 个词作为上下文
  → 累加到 M[目标词, 上下文词]
  → M 的每一行 = 一个词的稀疏向量
  → 余弦比较行与行 → 最近邻
```

实验语料特意设计成"自然语言"与"机器学习"出现在相同句型里：

```python
from collections import Counter
from math import log2

corpus = [
    ["我", "喜欢", "自然语言"],
    ["我", "喜欢", "机器学习"],
    ["自然语言", "很", "有趣"],
    ["机器学习", "很", "有趣"],
    ["我", "研究", "自然语言"],
    ["我", "学习", "机器学习"],
]


def word_context_counts(corpus, window=1):
    """统计“词—上下文”共现矩阵（用稀疏 dict 表示）。

    输入：corpus 是分好词的句子列表；window=1 表示只看左右各 1 个词。
    返回：Counter，键是 (目标词, 上下文词) 二元组，值是“上下文词出现在
          目标词窗口中”的次数。对称窗口下，每个相邻词对会被记两次
          （A 把 B 记为上下文，B 也把 A 记为上下文），这是词—上下文
          矩阵的标准计数方式，不影响余弦与 PMI 的结果。
    """
    counts = Counter()
    for sentence in corpus:
        for i, target in enumerate(sentence):
            # 窗口范围 [i-window, i+window]；max/min 防止越界（句首没有左邻）。
            for j in range(max(0, i - window), min(len(sentence), i + window + 1)):
                if i != j:  # 一个词不和它自己共现
                    counts[(target, sentence[j])] += 1
    return counts


counts = word_context_counts(corpus)
vocab = sorted({token for sentence in corpus for token in sentence})
total = sum(counts.values())  # 矩阵所有单元格的总和
row_sums = Counter()          # row_sums[w] = 词 w 作为“目标”的计数总和（行和）
for (w, c), count in counts.items():
    row_sums[w] += count

print(f"词表大小 = {len(vocab)}，矩阵总计数 = {total}")
print("自然语言 这一行（它作为目标词的上下文计数）：")
target_row = {c: count for (w, c), count in counts.items() if w == "自然语言"}
print(f"  {target_row}")
```

输出：

```
词表大小 = 8，矩阵总计数 = 24
自然语言 这一行（它作为目标词的上下文计数）：
  {'喜欢': 1, '很': 1, '研究': 1}
```

"自然语言"的向量是 $$\{$$喜欢: 1，很: 1，研究: 1$$\}$$：它跟在"喜欢"和"研究"后面，后面接"很"。这个 dict 就是共现矩阵一行的稀疏写法——8 个词的语料里矩阵是 $$8\times8$$，真实系统则是 $$|V|\times|V|$$ 的稀疏大矩阵。

## 4. 余弦与最近邻：什么算"相似"

余弦公式与 Day 011/014 完全相同，只是比较对象从文档换成了词：

```python
def context_vector(word, counts):
    """词 word 的上下文向量：取共现矩阵中 word 那一行的稀疏表示。"""
    return {c: count for (w, c), count in counts.items() if w == word}


def cosine(vec_a, vec_b):
    """稀疏向量的余弦相似度（与 Day 011/014 同一个公式）。"""
    dot = sum(vec_a[t] * vec_b.get(t, 0.0) for t in vec_a)
    na = sum(w * w for w in vec_a.values()) ** 0.5
    nb = sum(w * w for w in vec_b.values()) ** 0.5
    return dot / (na * nb) if na and nb else 0.0


def neighbors(word, vector_fn):
    """按余弦列出 word 的全部邻居，从近到远（不含自己）。"""
    target = vector_fn(word)
    scored = [
        (cosine(target, vector_fn(other)), other)
        for other in vocab
        if other != word
    ]
    return sorted(scored, reverse=True)


print("自然语言的邻居（原始计数向量）：")
for score, other in neighbors("自然语言", lambda w: context_vector(w, counts)):
    print(f"  cos(自然语言, {other}) = {score:.4f}")

onehot = {w: {w: 1} for w in vocab}  # one-hot：每词只有自己那一维是 1
print("\none-hot 对照：任意两个不同词的余弦")
print(f"  cos(自然语言, 机器学习) = {cosine(onehot['自然语言'], onehot['机器学习']):.4f}")
print(f"  cos(自然语言, 研究)     = {cosine(onehot['自然语言'], onehot['研究']):.4f}")
```

输出：

```
自然语言的邻居（原始计数向量）：
  cos(自然语言, 我) = 0.7071
  cos(自然语言, 机器学习) = 0.6667
  cos(自然语言, 有趣) = 0.5774
  cos(自然语言, 研究) = 0.0000
  cos(自然语言, 很) = 0.0000
  cos(自然语言, 学习) = 0.0000
  cos(自然语言, 喜欢) = 0.0000

one-hot 对照：任意两个不同词的余弦
  cos(自然语言, 机器学习) = 0.0000
  cos(自然语言, 研究)     = 0.0000
```

这份输出值得逐条精读，它包含本节最重要的三个事实：

**事实一：余弦度量的是"上下文分布的重叠"，不是"是否一起出现"。** "自然语言"与"机器学习"在全部 6 句话里**从未出现在同一窗口中**，余弦却高达 0.6667——因为它们共享上下文（都跟在"喜欢"后、都接"很"）。反过来，"自然语言"与"研究"直接相邻（"我研究自然语言"），余弦却是 0——一个的上下文是 $$\{$$喜欢、很、研究$$\}$$，另一个是 $$\{$$我、自然语言$$\}$$，两个集合不相交。**相似说的是"生活在同样的环境里"，不是"见过面"**。

**事实二：one-hot 把所有词变成孤岛。** 任意两个不同词的余弦恒为 0——这正是 Day 011 词汇鸿沟的几何本质。上下文向量第一次让"相近"有了可能。

**事实三：高频词会成为"中心枢纽"。** "我"以 0.7071 排在邻居榜首，压过了真正的同义词"机器学习"。原因："我"参与共现最多（行和最大），与谁都容易共享一点计数。这是原始计数的系统性偏差，下一节用加权修复。

## 5. PPMI：按"超出偶然的程度"加权

PMI（Pointwise Mutual Information，点互信息）衡量一个共现**比偶然相遇高出多少倍**：

$$
\operatorname{PMI}(w,c)=\log_2\frac{P(w,c)}{P(w)\,P(c)}
$$

其中 $$P(w,c)=\operatorname{count}(w,c)/\text{total}$$，$$P(w)$$、$$P(c)$$ 用行和除以 total 近似。直觉：若 $$w$$ 和 $$c$$ 只是随机碰上，PMI 约为 0；共现远超偶然则为正。PPMI（Positive PMI）把负值截断为 0——"比偶然还少见面"对相似性没有可解释的含义。

这个思路与 TF-IDF 精神相通：TF-IDF 用"在语料中稀有"给词加权，PPMI 用"共现超出预期"给词对加权，都是在**压掉平凡、放大意外**。

```python
def ppmi_vector(word, counts, total, row_sums):
    """把 word 的上下文计数换成 PPMI（正点互信息）权重。

    PMI(w,c) = log2 [ P(w,c) / (P(w)·P(c)) ]，度量“这对词的共现比偶然
    相遇多出多少倍”。P(w,c) = count/total，P(w) = 行和/total。
    PPMI = max(0, PMI)：低于偶然水平的词对直接记 0。
    """
    vector = {}
    for (w, c), count in counts.items():
        if w != word:
            continue
        p_wc = count / total
        p_w = row_sums[word] / total
        p_c = row_sums[c] / total  # 对称计数下，列和与行和相同
        vector[c] = max(0.0, log2(p_wc / (p_w * p_c)))
    return vector


print("自然语言 的两种向量对照：")
print(f"  原始计数：{context_vector('自然语言', counts)}")
ppmi_nl = ppmi_vector("自然语言", counts, total, row_sums)
print(f"  PPMI    ：{{{', '.join(f'{t}: {v:.3f}' for t, v in sorted(ppmi_nl.items()))}}}")
ppmi_wo = ppmi_vector("我", counts, total, row_sums)
print(f"  我(PPMI)：{{{', '.join(f'{t}: {v:.3f}' for t, v in sorted(ppmi_wo.items()))}}}")

print("\n自然语言的邻居（PPMI 向量）：")
for score, other in neighbors(
    "自然语言", lambda w: ppmi_vector(w, counts, total, row_sums)
):
    print(f"  cos(自然语言, {other}) = {score:.4f}")
```

输出：

```
自然语言 的两种向量对照：
  原始计数：{'喜欢': 1, '很': 1, '研究': 1}
  PPMI    ：{喜欢: 1.000, 很: 1.000, 研究: 2.000}
  我(PPMI)：{喜欢: 1.585, 学习: 1.585, 研究: 1.585}

自然语言的邻居（PPMI 向量）：
  cos(自然语言, 我) = 0.7071
  cos(自然语言, 有趣) = 0.4082
  cos(自然语言, 机器学习) = 0.3333
  cos(自然语言, 研究) = 0.0000
  cos(自然语言, 很) = 0.0000
  cos(自然语言, 学习) = 0.0000
  cos(自然语言, 喜欢) = 0.0000
```

三个观察：

* **稀有搭配被放大**："研究"只与"自然语言"搭配（行和小），PMI 达到 2 bits，超过"喜欢""很"（各 1 bit）。PPMI 偏爱意外性强的组合；
* **邻居顺序变了**："有趣"（0.4082）升到"机器学习"（0.3333）之前——因为"很-有趣"是超强的专属搭配。加权方式直接改变"谁是最相似的词"，这是词向量里反复出现的主题；
* **"我"没有被压下去，这是本语料的诚实结果**。教材常说 PPMI 能抑制高频功能词，但那需要功能词的共现**接近偶然水平**。在这 6 句话里，"我喜欢 X"是真实且强的句式，"我-喜欢"共现高出偶然 3 倍（PMI = 1.585），PPMI 不该也不会抹掉真实证据。规模上去之后，"的""是"这类与几乎所有词均匀共现的词，PMI 才会普遍趋近 0 而被压掉。

{% hint style="info" %}
PPMI 向量仍是 $$|V|$$ 维稀疏向量。经典做法是对 PPMI 矩阵做 SVD 降维得到稠密向量（LSA 思路）；现代做法是用神经网络直接学稠密向量（Day 016 起）。两条路线的起点都是今天这张共现表。
{% endhint %}

## 6. Embedding：矩阵的行、稠密与查表

**Embedding（嵌入）**的严格定义：一个映射 $$E:V\to\mathbb{R}^d$$，把词表里的每个词送到一个 $$d$$ 维稠密向量（$$d\ll|V|$$，典型 100–300）。三个等价视角：

* **查表**：$$E$$ 就是一张表，`embedding[w]` 返回第 $$w$$ 行；
* **矩阵行**：把所有向量堆成矩阵 $$\mathbf{E}\in\mathbb{R}^{|V|\times d}$$，词 $$w$$ 的向量是 $$\mathbf{E}$$ 的第 $$w$$ 行；
* **one-hot 乘矩阵**：$$\mathbf{e}_w^{\top}\mathbf{E}$$——one-hot 行向量选中那一行。神经网络里"Embedding 层"的数学本质就是这个乘法（Day 016 会用到）。

与第 3–5 节计数向量的两点区别：**维度**从 $$|V|$$（8、几万）降到 $$d$$（几十到几百）；**数值**从可解释的计数变成学出来的实数（不可直接读出含义，但几何结构承载语义）。

用一组手工设定的 2 维向量演示"几何承载语义"（数值是人为编的教学示例，不是训练结果；真实输出为程序计算）：

```python
embedding = {
    #        动物轴  交通工具轴
    "猫":   (0.90, 0.10),
    "狗":   (0.85, 0.15),
    "汽车": (0.10, 0.90),
    "卡车": (0.15, 0.85),
}


def embedding_cosine(a, b):
    """查表即取行：embedding[a] 就是矩阵第 a 行的 2 维稠密向量。"""
    (xa, ya), (xb, yb) = embedding[a], embedding[b]
    dot = xa * xb + ya * yb
    na = (xa * xa + ya * ya) ** 0.5
    nb = (xb * xb + yb * yb) ** 0.5
    return dot / (na * nb)


print("手工 2 维示例（数值为人为设定，只演示几何含义）：")
for a, b in (("猫", "狗"), ("汽车", "卡车"), ("猫", "汽车")):
    print(f"  cos({a}, {b}) = {embedding_cosine(a, b):.4f}")
```

输出：

```
手工 2 维示例（数值为人为设定，只演示几何含义）：
  cos(猫, 狗) = 0.9980
  cos(汽车, 卡车) = 0.9980
  cos(猫, 汽车) = 0.2195
```

同类词夹角小、跨类夹角大。关键问题是：**这张表从哪来？** 手工编只对 4 个词可行；词表 5 万时，就得让模型从语料里把每一行学出来——这正是 Day 016–018（Word2Vec 的训练目标、样本构造、负采样）要做的事，评价学得好不好的工具（余弦、最近邻）今天已经备齐。

## 7. 边界与特异性

* **静态一词一向量**：本节及 Word2Vec/GloVe 都给每个词型（type）一个固定向量——"苹果"（水果）与"苹果"（公司）共享同一个表示。上下文相关的表示留到 Day 020（静态 vs 上下文）与 ELMo/BERT 一线；
* **分词依赖**：共现统计建立在 Token 之上。中文按词还是按字切、英文去不去停用词，直接改变矩阵本身；第 1 周关于 Tokenizer 一致性的所有结论在这里同样适用；
* **窗口大小的语义**：小窗（1–2）偏句法与搭配（PMI 放大的"研究-自然语言"就是搭配），大窗（5–10）偏主题与领域。想要哪种"相似"，是选窗口的第一依据；
* **高频词与停用词**：真实语料中"的""是"与一切词共现，计数被它们淹没。PPMI 压制、停用词表、或下采样（Day 016 的 subsampling）是三种常见处理，选择应由近邻质量检验；
* **本节语料的规模声明**：6 句话的语料只为逐数字可手算。任何近邻结论都是教学演示，不是语言事实；真实词向量需要亿级 Token（Day 021 的实验会折中处理）。

## 8. 工程权衡与失效模式

* **维度选择**：$$d$$ 太小装不下语义结构，太大稀疏且昂贵；经验值 100–300，最终由下游任务验证；
* **余弦还是欧氏距离**：向量都归一化后二者排序等价。工程上常预先归一化，把余弦退化为点积，检索快一个量级（Day 080 的稠密检索直接受益）；
* **表大小与更新**：$$|V|\times d$$ 的浮点矩阵（5 万词 × 300 维 ≈ 6000 万参数）训练时要全量驻留；词表裁剪、哈希技巧（hashing trick）是常见瘦身手段；
* **计数式 vs 学习式**：PPMI+SVD 无需训练循环、可解释，但矩阵随语料线性膨胀；Word2Vec 直接学低维表、可增量更新，但引入训练超参。Day 016 之后会看到两者目标上的深层联系；
* **失效模式**：低频词向量不可靠（证据太少——Day 009 的稀疏性问题换了形态回来）；反义词常被分到很近（"好/坏"上下文几乎相同——分布式假设区分不了褒贬）；OOV 词没有向量（静态词表的固有问题，子词表示可缓解）。

## 9. 常见误区

### 误区一：分布式假设和分布式表示是一回事

前者是语言学论断（分布与语义相关），后者是表示方式（低维稠密向量）。用 one-hot 也能统计分布，用稠密向量也可以与分布无关（随机初始化）。

### 误区二：两个词经常一起出现，余弦就高

第 4 节实测："自然语言"与"研究"直接相邻，余弦为 0。余弦比较的是**上下文集合的重叠**，共现只是让彼此进入对方的上下文，不保证两个分布相似。

### 误区三：PPMI 就是 TF-IDF

直觉相通（压平凡、放大意外），但对象不同：TF-IDF 加权"词-文档"，PPMI 加权"词-上下文词"；分母一个是文档频率，一个是独立性期望。面试时说清这一句即加分。

### 误区四：稠密向量天然就有语义

维度低、数值稠密本身不产生语义。语义来自训练信号（共现统计）+ 分布式假设成立。随机初始化的 Embedding 也是稠密的，但毫无语义。

### 误区五：cos 接近 1 的两词可以互相替换

相似是分布层面的。反义词、搭配词（"有趣-很"）都可能高相似；替换是否成立要看下游任务。

## 练习与面试准备

### 30 秒口述题

请在 30 秒内回答：

> 什么是分布式假设？它怎样变成可计算的词向量？

合格答案应包含：上下文相似的词语义相似（Harris/Firth）；用滑动窗口统计词—上下文共现矩阵，每行是一个词的分布表示；用余弦比较分布、找最近邻；再经 PPMI 加权或神经网络学习压缩成稠密 Embedding。

### 基础题 1：手算共现与余弦

语料仅一句：`["我", "喜欢", "自然语言"]`，窗口为 1。写出"喜欢"的上下文向量，并计算 cos(我, 自然语言)。

<details>
<summary>参考答案</summary>

窗口 1 下，"我"的上下文 = $$\{$$喜欢: 1$$\}$$，"自然语言"的上下文 = $$\{$$喜欢: 1$$\}$$。两向量相同，点积为 1，模长都为 1，$$\cos=1$$。在单句语料里，"我"与"自然语言"共享唯一的上下文"喜欢"——这也是小语料结论不可信的极简例证。

</details>

### 基础题 2：手算 PMI

设共现矩阵总计数为 24；$$\operatorname{count}(\text{很},\text{有趣})=2$$，行和 $$\text{row}(\text{很})=4$$、$$\text{row}(\text{有趣})=2$$。计算 PMI(很， 有趣) 并说明它为何是正的。

<details>
<summary>参考答案</summary>

$$P(\text{很},\text{有趣})=2/24$$，$$P(\text{很})P(\text{有趣})=(4/24)\times(2/24)=8/576=1/72$$。比值 $$=(2/24)/(1/72)=6$$，$$\operatorname{PMI}=\log_2 6\approx2.585$$ bits。共现频率是独立期望的 6 倍，远超偶然，所以为正且较大。

</details>

### 进阶题 3：解释"相邻却为零"

本节实测 cos(自然语言, 研究) = 0 而 cos(自然语言, 机器学习) = 0.6667。前者直接相邻、后者从未同窗。请完整解释，并说明这为什么恰恰是分布式假设的正确行为。

<details>
<summary>参考答案</summary>

余弦比较上下文集合的交集：自然语言的上下文 $$\{$$喜欢、很、研究$$\}$$ 与研究的上下文 $$\{$$我、自然语言$$\}$$ 交集为空；与机器学习的上下文 $$\{$$喜欢、很、学习$$\}$$ 交集为 $$\{$$喜欢、很$$\}$$。分布式假设关心的是"生活在什么环境里"而非"是否见过面"：能互相替换的词（自然语言/机器学习都能填进"我喜欢__""__很有趣"）才是语义相近，而"研究"是自然语言的搭档，不是它的同类。

</details>

### 进阶题 4：代码审查

下面的共现统计实现有什么问题？

```python
def cooccur(corpus, window=1):
    counts = Counter()
    for s in corpus:
        for i, w in enumerate(s):
            for j in range(i + 1, len(s)):
                if j - i <= window:
                    counts[(w, s[j])] += 1
    return counts
```

<details>
<summary>参考答案</summary>

只统计了右侧邻居（`j` 从 `i+1` 开始），漏掉左邻——矩阵不再是标准的对称计数，"喜欢"能看到"自然语言"，"自然语言"却看不到"喜欢"，行向量系统性残缺。修法是窗口遍历 $$[i-\text{window}, i+\text{window}]$$ 并跳过 $$i=j$$（本节 `word_context_counts` 的写法）。

</details>

### 面试追问 5：PPMI 与 TF-IDF 的异同

同：都按"超出平凡预期的程度"加权，压高频、抬稀有。异：TF-IDF 处理"词—文档"关系，IDF 只看文档频率；PMI 处理"词—词"共现，需要同时考虑两个边际的独立期望。回答时能主动说"一个是检索权重、一个是关联度量"更佳。

### 面试追问 6：窗口大小怎么选

小窗（1–2）捕捉句法与搭配，适合词性敏感的任务；大窗（5–10）捕捉主题与领域，适合语义相似与检索。没有唯一正确值，标准做法：固定下游评价（相似度测试集、近邻人工抽查），对窗口做消融后选择，并声明取值。

### 项目答辩题 7：从 BM25 升级到语义检索的路线

Day 014 的搜索器有词汇鸿沟。给出升级路径与每步的证据要求。

答题要点：短期用同义词表/查询改写（Day 088），零训练成本，收益用 Recall@K 度量；中期引入静态词向量做查询/文档扩展或语义召回（今天的近邻可做查询扩展），证据为同义改写查询集上的召回提升与误扩展率；长期走稠密检索（Day 080，双编码器）+ 混合排序（Day 083），需要训练数据与向量库，证据为离线评价 + 在线 A/B。任何一步都要保留 BM25 基线对照，防止"新方法在简单查询上退步"被平均分掩盖。
