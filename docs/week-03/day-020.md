## 1. 静态向量的天花板

Day 015–018 的所有方法（共现计数、PPMI、Word2Vec、GloVe）共享同一个承诺：**词表中的每个词型（type）对应一个固定向量**。查一次表，无论这个词出现在什么句子里，向量不变。

这对无歧义的词没有问题。但语言里充满多义词：

* "苹果"：水果 vs 公司；
* "bank"：河岸 vs 银行；
* "打"：打电话、打篮球、打车……

静态向量只能给它们**各一个**向量。训练语料里两个义项都出现时，这个向量是两个"理想义项向量"按语料频率的加权混合。Day 015 反义词相近的根源（上下文分布被合并统计）在这里以更尖锐的形式重现。

## 2. 实验 A：双义语料与混合近邻

构造一个小语料："苹果"出现在两类句子中——水果语境（吃、甜）和公司语境（发布、手机）；"香蕉"只出现在水果语境、"小米"只出现在公司语境，它们是两个义项的"同类词"：

```python
from collections import Counter

corpus = [
    ["我", "吃", "苹果"],        # 水果义
    ["苹果", "很", "甜"],        # 水果义
    ["我", "吃", "香蕉"],        # 水果义（香蕉：苹果的同类词）
    ["香蕉", "很", "甜"],        # 水果义
    ["苹果", "发布", "手机"],    # 公司义
    ["小米", "发布", "手机"],    # 公司义（小米：苹果的同类词）
    ["小米", "是", "公司"],      # 公司义
]


def word_context_counts(corpus, window=1):
    """词—上下文计数（与 Day 015 相同的方法）。"""
    counts = Counter()
    for sentence in corpus:
        for i, target in enumerate(sentence):
            for j in range(max(0, i - window), min(len(sentence), i + window + 1)):
                if i != j:
                    counts[(target, sentence[j])] += 1
    return counts


def context_vector(word, counts):
    """词 word 的静态向量：共现矩阵中 word 那一行。"""
    return {c: n for (w, c), n in counts.items() if w == word}


def cosine(vec_a, vec_b):
    dot = sum(vec_a[t] * vec_b.get(t, 0.0) for t in vec_a)
    na = sum(w * w for w in vec_a.values()) ** 0.5
    nb = sum(w * w for w in vec_b.values()) ** 0.5
    return dot / (na * nb) if na and nb else 0.0


counts = word_context_counts(corpus)
vocab = sorted({t for s in corpus for t in s})
print("苹果 的静态向量：", context_vector("苹果", counts))
print("香蕉 的静态向量：", context_vector("香蕉", counts))
print("小米 的静态向量：", context_vector("小米", counts))

print("\n静态近邻（苹果，全部词）：")
apple = context_vector("苹果", counts)
ranked = sorted(
    ((cosine(apple, context_vector(w, counts)), w) for w in vocab if w != "苹果"),
    reverse=True,
)
for score, w in ranked:
    tag = "水果义同类" if w in ("香蕉", "甜", "吃") else ("公司义同类" if w in ("小米", "手机", "发布", "公司") else "")
    print(f"  cos(苹果, {w}) = {score:.4f}   {tag}")
```

输出：

```
苹果 的静态向量： {'吃': 1, '很': 1, '发布': 1}
香蕉 的静态向量： {'吃': 1, '很': 1}
小米 的静态向量： {'发布': 1, '是': 1}

静态近邻（苹果，全部词）：
  cos(苹果, 香蕉) = 0.8165   水果义同类
  cos(苹果, 甜) = 0.5774   水果义同类
  cos(苹果, 手机) = 0.5774   公司义同类
  cos(苹果, 我) = 0.5774
  cos(苹果, 小米) = 0.4082   公司义同类
  cos(苹果, 是) = 0.0000
  cos(苹果, 很) = 0.0000
  cos(苹果, 吃) = 0.0000   水果义同类
  cos(苹果, 发布) = 0.0000   公司义同类
  cos(苹果, 公司) = 0.0000   公司义同类
```

"苹果"的静态向量 $$\{$$吃: 1，很: 1，发布: 1$$\}$$ 把两个义项的上下文**合并**统计了。结果在近邻表上一目了然：第一名是水果同类的"香蕉"，但"手机"（公司同类）与"甜"并列第二，"小米"紧随其后——**近邻名单里两个义项混作一团**。这不是训练不充分，是表示形式的上限：再多的语料、再好的算法，也只能把这个混合物估得更准，无法把它拆开。

## 3. 拆分的思想实验：如果有人工标注

假如有一位标注员告诉我们每次"苹果"是哪个义项，就能分开统计两份共现：

```python
fruit_vector = {"吃": 1, "很": 1}       # 来自“我吃苹果”“苹果很甜”
company_vector = {"发布": 1}            # 来自“苹果发布手机”

print("拆分后的义项向量与近邻：")
for name, vec in (("苹果(水果义)", fruit_vector), ("苹果(公司义)", company_vector)):
    print(f"  {name} = {vec}")
    for w in ("香蕉", "小米"):
        print(f"    cos({name}, {w}) = {cosine(vec, context_vector(w, counts)):.4f}")
```

输出：

```
拆分后的义项向量与近邻：
  苹果(水果义) = {'吃': 1, '很': 1}
    cos(苹果(水果义), 香蕉) = 1.0000
    cos(苹果(水果义), 小米) = 0.0000
  苹果(公司义) = {'发布': 1}
    cos(苹果(公司义), 香蕉) = 0.0000
    cos(苹果(公司义), 小米) = 0.7071
```

拆开后各自干净：水果义只亲近"香蕉"，公司义只亲近"小米"。但这条路有个致命前提——**义项标注（词义消歧，word sense disambiguation）本身就是难题**，而且词表有数万词、语料有数十亿词，人工标注不可扩展。真正可行的方向是反过来：**不标注义项，而是让向量直接依赖出现语境**。

## 4. 上下文表示：定义与它在架构里的位置

上下文表示的严格定义：词 $$w$$ 在句子 $$s$$ 中的向量记为 $$v(w,s)$$——**同一个词型，不同句子，不同向量**：

```
输入：吃 苹果 甜          →  v(苹果, “吃苹果甜”)   偏水果义
输入：发布 苹果 手机      →  v(苹果, “发布苹果手机”) 偏公司义
```

历史脉络一句话：ELMo（2018，双层双向 LSTM）首次让上下文向量大规模刷榜；BERT（2018，Transformer 编码器）把它推向主流；GPT 系（解码器）同样输出上下文向量。架构细节属于 Day 024、Day 044，今天记住一个**架构事实**就够：

```
Token 查表（静态，Day 015 的 Embedding）
  ↓
上层网络（LSTM / Transformer，读取整句）
  ↓
每个位置的隐状态 = 该位置 Token 的上下文向量 v(w, s)
```

**Embedding 层本身仍然是静态查表**——上下文化不是发生在查表里，而是发生在查表之上的网络层里。这个澄清很关键：现代 LLM 的"词向量"分两层，底层查表给每个 Token 一个起点向量，上层网络根据整句把它改写成上下文向量。

## 5. 实验 B：玩具级上下文化

用最简单的可计算机制演示"同词不同句 → 不同向量"：静态向量加上窗口内邻居静态向量的平均（$$\alpha$$ 控制上下文分量的强度）：

$$
v(w,s)=v_{\text{static}}(w)+\alpha\cdot\frac{1}{|s|}\sum_{c\in\text{窗口}(s)}v_{\text{static}}(c)
$$

```python
def contextual_vector(word, sentence, counts, window=1, alpha=2.0):
    """玩具版“上下文向量”：静态向量加上邻居静态向量的平均。

    真实的 ELMo/BERT 用整个序列经深度网络生成上下文向量；
    这里用最简单的加法合成演示“同一词在不同句中得到不同向量”。
    """
    vec = dict(context_vector(word, counts))  # 复制静态向量，避免原地修改
    idx = sentence.index(word)
    contexts = [
        sentence[j]
        for j in range(max(0, idx - window), min(len(sentence), idx + window + 1))
        if sentence[j] != word
    ]
    # 对齐两套稀疏向量的全部维度，把窗口内上下文的平均加到目标词上
    dims = set(vec)
    for c in contexts:
        dims.update(context_vector(c, counts))
    for dim in dims:
        ctx_avg = sum(context_vector(c, counts).get(dim, 0) for c in contexts) / len(contexts)
        vec[dim] = vec.get(dim, 0) + alpha * ctx_avg
    return vec


fruit_sentence = ["吃", "苹果", "甜"]
company_sentence = ["发布", "苹果", "手机"]

apple_fruit = contextual_vector("苹果", fruit_sentence, counts)
apple_company = contextual_vector("苹果", company_sentence, counts)

print("玩具上下文化（α=2.0，窗口=1）：")
print(f"  苹果@{fruit_sentence} 与 苹果@{company_sentence} 的余弦 = "
      f"{cosine(apple_fruit, apple_company):.4f}")
print("  （静态向量自己与自己恒为 1.0）")
print(f"  cos(苹果@水果句, 香蕉) = {cosine(apple_fruit, context_vector('香蕉', counts)):.4f}")
print(f"  cos(苹果@水果句, 小米) = {cosine(apple_fruit, context_vector('小米', counts)):.4f}")
print(f"  cos(苹果@公司句, 香蕉) = {cosine(apple_company, context_vector('香蕉', counts)):.4f}")
print(f"  cos(苹果@公司句, 小米) = {cosine(apple_company, context_vector('小米', counts)):.4f}")
```

输出：

```
玩具上下文化（α=2.0，窗口=1）：
  苹果@['吃', '苹果', '甜'] 与 苹果@['发布', '苹果', '手机'] 的余弦 = 0.4706
  （静态向量自己与自己恒为 1.0）
  cos(苹果@水果句, 香蕉) = 0.6860
  cos(苹果@水果句, 小米) = 0.1715
  cos(苹果@公司句, 香蕉) = 0.3430
  cos(苹果@公司句, 小米) = 0.5145
```

三个观察：

* **同一个词分开了**：两个"苹果"的余弦从 1.0（静态自比）降到 0.4706——上下文把它们推向了空间的不同区域；
* **近邻随句子翻转**：水果句里的苹果第一近邻是香蕉（0.6860 > 0.1715）；公司句里的苹果第一近邻变成小米（0.5145 > 0.3430）。同一个词，在不同的句子里"意思靠近不同的同类词"——这正是第 2 节静态向量做不到的事；
* **机制极简的诚实声明**：加法合成只是最粗的演示。真实模型用整句经深度网络生成上下文向量，"上下文化到什么程度"由训练学出来而不是手工 $$\alpha$$。本玩具的价值是把"向量依赖语境"这件事变成可以逐位核对的数字。

## 6. 工程对比：静态与上下文各就各位

| 维度 | 静态表示（Word2Vec/GloVe/fastText） | 上下文表示（ELMo/BERT/现代 LLM 隐状态） |
| --- | --- | --- |
| 向量来源 | 查表，O(1) | 整句过一遍模型 |
| 计算代价 | 预计算一次，推理近零 | 每句一次前向传播 |
| 存储 | 词表 × d 的一张表 | 模型本体 + 每句每层每位置的向量 |
| 多义词 | 混合，无法拆分 | 按语境自动分化 |
| OOV | 无向量（fastText 子词可拼） | 子词 Tokenizer 天然泛化 |
| 典型用途 | 词级特征、轻量检索、Embedding 层底座 | 分类/抽取/检索编码/生成 |

结论不是"上下文取代静态"，而是**分工**：

* 需要**词级、海量、低延迟**的场合（候选召回的词特征、规则系统、Embedding 层的底座），静态向量仍是性价比之王；
* 需要**句内语义、歧义消解、组合理解**的场合（Day 080 的稠密检索、分类、重排），上下文表示是标准答案。

## 7. fastText 与子词：静态阵营的 OOV 解

静态向量还有 Day 015 提过的另一个软肋：词表固定，新词无向量。fastText 的解法与第 1 周的子词思想一脉相承：把词表示为**字符 n-gram 的袋子**，词向量 = 其子词向量之和。

* "苹果汁"不在词表？它的子词（"苹果"、"<苹果"、"...汁"等 n-gram）大都在——拼出一个合理的向量；
* 代价：每个词要存/算多个子词向量；受益：OOV、拼写变体、形态丰富的语言（德语、芬兰语）。

这是"静态 + 子词"对"上下文"的一次中间路线回应：保留了查表效率，用组合性换回部分泛化。现代 LLM 干脆全面转向字节/子词 Tokenizer（Day 004–007），从根上把 OOV 问题改写成"未见组合"问题。

## 8. 边界与特异性

* **层选择问题**：BERT 有 12（或更多）层，每层每位置都有向量——用哪一层当"词向量"是超参数。经验：中层常比顶层更适合句法/词义任务，顶层更贴合预训练目标；正式使用前必须在自己的任务上验证（Day 049 实验会涉及）；
* **中文的词与字**：中文静态向量按词训练依赖分词器（Day 015 的边界依旧）；按字训练词表小但歧义更重。上下文模型普遍按字或子词切分，绕开分词一致性问题；
* **跨类型不可比**：静态向量的余弦与上下文向量的余弦不在同一空间，不能混在一个近邻索引里比较（Day 080 混合检索要分别建索引再融合）；
* **静态向量的"过时"是伪命题**：现代 LLM 的输入层仍是静态查表（Day 015 的 $$E:V\to\mathbb{R}^d$$）；变化的只是上面叠了多少层上下文网络。

## 9. 常见误区

### 误区一：BERT 的 Embedding 层是上下文表示

Embedding 层是静态查表；上下文化发生在其上的 Transformer 层。"BERT 的词向量"严格说是各层隐状态，而隐状态每层每句都不同。

### 误区二：静态向量训练得更好就能解决多义词

不能。一词一向量的形式上限就是混合，语料与算法只能让混合估计更准。拆分必须改变表示形式（上下文化）或引入外部标注（义项标注）。

### 误区三：GloVe 是上下文表示

GloVe 与 Word2Vec 同属静态：基于全局共现计数（Day 015 的路线）学一张固定表，每个词一个向量。

### 误区四：fastText 解决了多义问题

子词方案缓解的是 OOV 与形态变体，向量仍按词型固定——多义混合原样存在。

### 误区五：上下文向量的相似度可以直接和静态向量比

两套向量在不同空间，数值尺度无关联。任何"混搭比相似度"的流程都是错误设计，需要分别索引后融合分数。

### 误区六：上下文表示在所有任务上都更好

词级词典任务、超低延迟场景、无 GPU 环境，静态向量常常仍是正确选择。表示选择由任务、预算与延迟共同决定，不是无脑追新。

### 进阶题 3：解释架构分工

为什么"Embedding 层静态查表 + 上层网络上下文化"是合理的分工？从效率与表达两方面回答。

<details>
<summary>参考答案</summary>

效率：查表 $$O(1)$$ 提供每个 Token 的起点，无重复计算；若要求第一层就上下文相关，等价于把整句信息编码进 $$|V|\times d$$ 的表，存储与统计上都不可行。表达：上下文化需要组合任意长度、任意内容的句子，天然是序列到序列的函数，正是上层网络的工作。两层分工 = "词的先验知识"与"句中的现场改写"。

</details>

### 进阶题 4：代码审查

下面的玩具上下文化实现有什么问题？

```python
def ctx(word, sentence, counts, alpha=2.0):
    vec = context_vector(word, counts)
    idx = sentence.index(word)
    for j in range(len(sentence)):
        if j != idx:
            for dim, val in context_vector(sentence[j], counts).items():
                vec[dim] = vec.get(dim, 0) + alpha * val
    return vec
```

<summary>参考答案</summary>

窗口被换成"整句"（可接受但须声明）；更严重的是邻居向量**求和而非平均**——句子越长上下文分量越大，$$\alpha$$ 的语义随句长漂移；且对 `vec`（静态向量的引用）原地修改会污染静态表本身，第二次调用同词时结果已经变了。修法：复制向量、按邻居数平均（本节实现的两个要点）。

### 面试追问 5：词相似度评测如何对待多义词

词相似度数据集（WordSim、SimLex 类）给词对一个平均分，多义词的分数本身是义项混合，静态向量在这些集上的"上限"受限；SimLex-999 特意选抽象/动词并控制关联性，部分缓解。更公平的评测是带语境的数据集（WiC：给定两句判断同一词是否同义）——上下文模型的优势在这里显现。

### 面试追问 6：检索系统里两套向量怎么配合

典型流水线：BM25（Day 011–014）+ 静态向量扩展做快速召回；上下文编码器（Day 080 双塔）做语义召回与重排；两路分数各自归一化后融合（Day 083 混合检索）。要点是"各自索引、分数融合"，不能把静态与上下文向量放进同一个近邻索引。

### 项目答辩题 7：为客服意图分类系统选择表示并论证

答题要点：先看数据量与延迟预算——短查询、高频调用、GPU 有限时，TF-IDF/fastText 特征 + 轻量分类器是稳健基线，报告其准确率与 P99 延迟作为下界；歧义多的长查询（"苹果怎么退款"既是产品又是动作）引入上下文编码器微调，报告提升幅度与额外成本；两者可级联：静态初筛 + 上下文精判。所有结论以同一测试集对比为准，并做按查询长度/歧义度的切片分析。
